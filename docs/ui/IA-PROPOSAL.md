# 구성 다시 짜기 — 전자계약을 «날릴 수 있게»

대표 2026-09-16: 「기능만 하고 어떻게 구성할건지 고민좀 해봐 기존처럼 뭐 4탭 이렇게
하지말고 **전자계약을 날릴수 있게끔 가능성 열어두고** ui ux어떻게 할건지 완전 새롭게
기존거 탈피하고」

---

## 0. 먼저 — 내가 틀리게 깔았던 전제

메뉴 넷을 짤 때 나는 **전자계약을 «장소»로 놨다.** 그게 틀렸다.

```
상품찾기 · 계약접수 · 정산관리 · 전자계약
                                 ↑ 여기가 틀렸다
```

전자계약은 장소가 아니라 **한 접수의 「계약서」 칸이 펼쳐진 것**이다. 근거 셋:

1. **접수 원장의 진행은 이미 넷이다** — `계약서 · 필수서류 · 잔금 · 인도`.
   전자계약 5단계(작성·발송 전·고객 작성 중·검토 대기·완료)는
   그 중 **「계약서」 한 칸의 안쪽**이다. 새 축이 아니다.
2. **fp4 가 축을 둘로 가른 이유가 그대로 적용된다.**
   `contractStage`(우리 일) vs `esign`(손님). 우리 「우리 일」 축은 **이미 접수의 진행 넷**이다.
   전자계약을 메뉴로 세우면 세 번째 축을 만드는 셈이다.
3. **fp4 에 이미 `contract_source: erp | excel | direct` 가 있다.**
   저쪽도 「계약서가 어떻게 들어왔는지」를 **갈아끼울 수 있는 것**으로 본다.

★메뉴로 세우면 **같은 건이 두 목록에 산다.** 대표가 매일 두 곳을 열고,
어느 쪽이 맞는지 세션마다 갈리는 그 문제가 화면에서 또 생긴다.

## 1. 「날릴 수 있다」는 게 무슨 뜻인가 — 요구를 먼저 굳힌다

날린다 = 착한거래를 끊거나, 다른 데로 갈아타거나, **종이 계약으로 되돌린다**.
그게 되려면 **의존이 한 방향**이어야 한다.

```
  접수 원장                                   갈아끼우는 자리
 ┌────────────────────────────┐            ┌──────────────────┐
 │ 진행 넷                     │            │  계약 어댑터       │
 │  ■ 계약서   ← 이 칸만 채운다 │◀───────────│   erp   착한거래   │
 │  □ 필수서류                 │            │   excel 엑셀 양식  │
 │  □ 잔금                     │            │   direct 직접입력  │
 │  □ 인도                     │            │   paper 종이 ★     │
 └────────────────────────────┘            └──────────────────┘
   계약서 칸이 «아는» 것                        계약서 칸이 «모르는» 것
     done · at · source · ref                   링크 · 단계 · 해시 · 제공자
```

★**접수는 어댑터를 모른다.** 어댑터가 접수의 칸을 채운다.
그래서 어댑터를 지우면 그 칸이 **다시 사람이 찍는 체크 한 칸**으로 돌아간다.
화면도 데이터도 안 무너진다.

지금 코드가 이 경계를 어기고 있는 곳 — 접수 상세의 주 단추가 「계약서 발송」이고
`S.screen = 'esign'` 으로 건너뛴다. **접수가 전자계약을 알고 있다.** 이것부터 끊는다.

## 2. 구성안 — 메뉴 «셋»

```
  상품찾기            계약접수                   정산관리
  ───────            ─────────                 ───────
  찾는 «도구»         하루를 여기서 산다          돈
  가끔 연다           ★매일 여는 화면은 «하나»    월말에 연다
```

전자계약 메뉴는 **없다.** 대신 계약접수 안에서 이렇게 산다.

### 2-1. 계약접수 화면 — 「목록 둘」을 「큐 + 원장」으로 바꾼다

기존 4탭(`칠 것 / 전체 / 인도완료 / 취소`)은 **상태 바구니**다.
바구니는 「무엇이 있나」를 말하지 「**무엇을 하나**」를 말하지 않는다.
그래서 갈래를 **«막힌 칸» 기준**으로 바꾼다.

```
┌─ 좌상 ── 오늘 할 일 ────────────────────────────────────┐
│ ⌕ 찾는 칸            [링크 3][검토 1][서류 2][잔금 1][인도 2]│  ← 갈래 = 막힌 칸
│ ────────────────────────────────────────────────────── │
│ 김서연  싼타페 MX5  서울12가3456  │ 검토 대기 │ 4시간째    │
│ 이서진  싼타페 TM   경기78나1204  │ 링크 만들기│ 확인 필요 ● │
│ 정하늘  그랜저 GN7  서울34다7781  │ 서류 대기 │ 보완 1차    │
│ ────────────────────────────────────────────────────── │
│ 칠 것 9   가장 오래 걸린 것 3일                          │  ← .pf 셈
└────────────────────────────────────────────────────────┘
┌─ 좌하 ── 접수 원장 (전체) ──────────────────────────────┐
│ ⌕ 찾는 칸  [전체][진행][인도완료][취소]                  │
│ … 기존 목록 그대로. «훑는» 자리다                        │
└────────────────────────────────────────────────────────┘
┌─ 우 ── 접수 상세 «하나» ────────────────────────────────┐
│ ① 접수 확인 ❯ ② 서류 확인 ❯ ③ 인도 처리                  │
│ [사진]  김서연 · 싼타페 MX5 · 1,090,000원/월             │
│ ─ 진행 ───────────────────────────────────────────────  │
│   계약서    검토 대기 ▾  09-16 15:10   [펼치기]          │  ← ★여기가 전자계약
│   필수서류  대기        —              [완료 처리]       │
│   잔금      대기        —              [완료 처리]       │
│   인도      대기        —              [완료 처리]       │
│ ─ 이력 ──────────────────────────────────────────────── │
│ [⋯] [링크 복사]                              [ 승인 ]   │  ← 주 단추 = 막힌 칸의 행동
└────────────────────────────────────────────────────────┘
```

### 2-2. ★「계약서」 줄을 펼치면 — 그 자리에서 열린다

새 화면으로 «가지» 않는다. 진행 표의 그 줄 아래가 열린다.

```
  계약서    검토 대기 ▾  09-16 15:10                    [접기]
  ┌────────────────────────────────────────────────────┐
  │ ① 작성 ❯ ② 발송 전 ❯ ③ 고객 작성 중 ❯ ④ 검토 대기 ❯ ⑤ 완료│
  │ 고객이 간 길  ●●●●●●●● 8/8 제출까지 마쳤다            │
  │ 낸 서류  신분증 15:02 · 면허 15:03 · 재직 15:08       │
  │ 링크  freepasserp.com/sign/E-2609-041                │
  └────────────────────────────────────────────────────┘
```

**전자계약을 날리면** 이 펼침이 없어지고 `[완료 처리]` 체크 한 칸으로 돌아간다.
스테퍼·목록·상세·메뉴 **아무것도 안 바뀐다.**

### 2-3. 「계약만 몰아 보고 싶다」는 어떻게 되나

그게 이 안의 유일한 약점이다. 답은 **갈래**다 —
큐에서 `[링크 3]` `[검토 1]` 을 누르면 계약 일만 남는다.
목록을 하나 더 만들지 않고 같은 큐를 거른다.

## 3. 안 고른 것들 — 왜 안 골랐나

| 안 | 뭐 | 왜 버렸나 |
|---|---|---|
| **B** 메뉴 넷 유지, 전자계약은 접수 목록의 «걸러진 보기» | 메뉴만 지우면 날려진다 | 여전히 **두 곳을 연다**. 「걸러진 보기」인 걸 화면이 말하지 않으면 사람은 두 원장으로 읽는다 |
| **C** 메뉴를 「찾기 / 오늘 할 일 / 돈」 으로 | 가장 급진적 | 방향은 맞다. 실은 **위 2안이 C의 핵심을 계약접수 안에 넣은 것**이다. 메뉴 이름까지 바꾸는 건 접수·정산이 실제로 도는 걸 본 뒤에 한다 |
| **D** 전자계약을 모달/시트로 | 목록 어디서든 띄운다 | 하루 여덟 시간 보는 판에서 모달은 **자리를 잃게 만든다**. 겹쳐 띄우면 이력과 진행을 나란히 못 본다 |

## 4. 이렇게 하면 무엇이 달라지나

| | 지금 | 바꾸면 |
|---|---|---|
| 매일 여는 화면 | 둘 (계약접수 · 전자계약) | **하나** |
| 같은 건이 사는 목록 | 둘 | 하나 (큐는 원장의 «보기») |
| 전자계약 제거 비용 | 메뉴·화면·상세 셋을 들어냄 | **펼침 하나 + 갈래 둘** |
| 「지금 뭐 해야 하나」 | 목록 두 개를 훑어 판단 | 큐 맨 위 줄 |
| 접수 → 계약 의존 | 접수가 전자계약을 안다 (`S.screen='esign'`) | **모른다.** source 만 안다 |

## 5. 결정할 것

1. **메뉴 셋으로 줄이나** — 전자계약 메뉴를 없애는 결정
2. **좌상을 「오늘 할 일」 큐로 바꾸나** — 상태 바구니 → 막힌 칸 갈래
3. 큐의 갈래를 무엇으로 두나 — 위 안은 `링크 · 검토 · 서류 · 잔금 · 인도` 다섯.
   여기에 「확인 필요」를 **갈래로 두지 않는다** (플래그다 — fp4 가 겪고 고친 문제)

## 6. 고른 것 (대표 2026-09-16)

| 물음 | 고른 답 |
|---|---|
| 메뉴 | **넷 유지.** 전자계약은 «보기» — 원장을 소유하지 않는다 |
| 좌상 갈래 | **막힌 칸으로** — 「4탭」은 메뉴가 아니라 목록 갈래 얘기였다 |

```
접수 목록   [칠 것 2][계약 2][서류 0][잔금 0][인도 0]  [전체 6][취소 1]
계약 보기   [링크 만들기][검토 대기][기다리는 중][링크 다시][전체]
```

★「칠 것 2」는 눌러서 줄을 열어봐야 뭘 할지 안다. 「계약 2」는 **누르기 전에** 안다.

### 6-1. 짓다가 «바로» 걸린 것 — 두 원장이면 어긋난다

표본을 짜자마자 났다. 이서진이 접수에는 `contract:true` 인데 전자계약은 「발송 전」이었다.
**같은 사실을 두 군데 적어 두면 반드시 어긋난다.**

그래서 계약서 칸을 **파생값**으로 바꿨다 (`stepDone`):

```
전자계약이 붙어 있으면 → e.stage === 'done'  를 읽는다 (a.contract 를 «안» 읽는다)
붙어 있지 않으면      → a.contract          를 읽는다 (저장된 값이 그대로 산다)
```

### 6-2. ★「날릴 수 있다」를 «실행해» 확인했다

`ESIGNS` 를 통째로 비우고 화면을 다시 그렸다.

| | 전자계약 있을 때 | 날린 뒤 |
|---|---|---|
| 진행표 | `계약서 전자계약 = 검토 대기 → 접기` | `계약서 = 대기 → 완료 처리` |
| | 필수서류 · 잔금 · 인도 대기 | **네 줄 그대로** |
| 주 단추 | 승인 | 계약서 완료 처리 |
| 갈래 | 칠 것2 계약2 서류0 잔금0 인도0 전체6 취소1 | **같은 일곱** (수만 바뀐다) |
| 전자계약 화면 | 목록 | 빈 상태 — 메뉴만 지우면 끝 |
| 터졌나 | — | **안 터졌다** |

접수가 전자계약을 아는 곳은 `blocked()` 와 `stepDone()` 의 **두 줄**뿐이고,
둘 다 `ecOf(a)` 가 `null` 이면 저장된 값으로 되돌아간다.
