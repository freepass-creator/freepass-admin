# 정산원장 실적 — 어떤 항목을 넣나

> 대표 2026-09-17 「지금 현재 정산원장 실적을 그대로 갖고 와야하거든 어떤 항목을 넣을건지랑」

원천 : **ERP5**(Firebase `freepasserp5`) Firestore `settlement_rows` — **461줄 · 72칸**
실측 : 2026-09-17 · 읽기만 함 · 개인정보 칸은 값을 안 찍음

## 0. ★옮기기 «전에» 대표가 봐야 할 것 둘

### ① 2026-05 에 청구가 **47줄 비어 있다** — 지급만 나갔다

```
2026-05   64줄   청구 30,895,367   지급 66,805,931   차 ▲ -35,910,564
          ├ 청구 0 인 줄 47  (지급 0 인 줄은 0)
          └ 그 47줄의 지급 합 36,441,900
```

다른 달은 전부 +1,000만 안팎인데 5월만 **마이너스 3,591만**이다.
`stage` 는 「청구」로 돼 있는데 `claimWritten` 이 0 이다 — 청구했다고 적혀 있는데 금액이 없다.

★**이게 전체 마진을 반으로 깎고 있었다.**

| | 청구 | 지급 | 남는 것 | |
|---|---|---|---|---|
| 461줄 전부 | 474,633,200 | 424,407,933 | 50,225,267 | **10.6%** |
| **5월 뺀 397줄** | 443,737,833 | 357,602,002 | 86,135,831 | **19.4%** |
| F04 매뉴얼 §18 실측(341줄) | 401,419,799 | 323,870,861 | 77,548,938 | **19.3%** |

**5월을 빼면 19.4% 로 매뉴얼의 19.3% 와 맞는다.** 어제 제가 「마진이 두 정본에서 다르다」고 한 것의 정체가 이것이다 — 정본이 다른 게 아니라 **5월 47줄이 구멍**이다.

> 전체로 53줄(빈칸 4 · 5월 47 · 8월 2)이 「지급은 있는데 청구가 0」 이고, 그 지급 합이 **39,903,880** 이다.

⚠ 이 47줄을 **0 으로 옮기면 안 된다.** 「청구 0원」이 아니라 「**모른다**」다.
0 으로 담으면 다음 사람이 「이 건은 청구 안 하는 건」으로 읽는다.

### ② 요율 칸에 «정액»이 섞여 있다 — 131줄

`supplierRate` 461줄 중 — **비율 299 · ★정액 131 · 0 이 31**

```
175수1279  오토플러스  supplierRate = 1,000,000   claimWritten = 1,000,000
                      rent×term = 20,400,000
                      ★비율로 읽으면 20,400,000,000,000 원이 된다
```

공급사 여섯이 이렇다 — **오토플러스 · 웰릭스 · 스타스카이 · 리더스렌트카 · 센트로 · 아이카**.
이 공급사들은 **요율이 아니라 대당 정액 수수료**로 정산한다.

★**한 칸에 뜻이 둘이면 언젠가 샌다.** 옮길 때 갈라 담는다.

## 2. **고쳐서** 넣는 항목 — 그대로 옮기면 안 되는 것

| ERP5 칸 | 지금 | 어떻게 바꿔 넣나 |
|---|---|---|
| `supplierRate` `agentRate` | ★비율 299 · **정액 131** 이 한 칸에 | **둘로 가른다** — `feeMode: 'RATE' \| 'FLAT'` + `supplierRate` / `supplierFlat`. 옮길 때 `>1` 이면 FLAT 으로 찍고, 그 판정을 **줄에 남긴다** |
| `claimWritten` = 0 (53줄) | 0 | ★**`null`(모른다)로 담는다.** 0 은 「청구 안 함」이라는 «사실»이고 지금은 그 사실을 모른다 |
| `stage` `claimStage` `payStage` | 셋이 따로 | `claimStage`(접수 319/청구 141/정정 1) 와 `payStage`(접수 141/확인 38/통보 282)만 남긴다. `stage` 는 `claimStage` 와 **값이 똑같다** — 같은 사실을 두 칸에 두지 않는다 |
| `settleRatio` | 1=454 · 0.5=7 | 그대로 넣되 **1 이 아닌 7줄에 까닭(`settleNote`)을 붙여** 담는다 |
| `note` `settleNote` `carryNote` | 13 / 7 / 2% | 글이라 기계가 못 읽는다. **원문 그대로** 싣고, 뜻이 굳으면 그때 칸을 세운다 |

## 3. **안 넣는** 항목 — 왜 안 넣나

| ERP5 칸 | 왜 |
|---|---|
| `stage` | `claimStage` 와 값이 같다. 중복 |
| `intakeKind` | 461줄 **전부 「영업수수료」** 하나뿐. 가르는 게 없으면 칸이 아니다 |
| `settleExclude` `billHold` | **0건.** 쓰인 적이 없다. 필요해지면 그때 만든다 |
| `collectedAmt` `paidAmt` `channelFixAmt` | **전부 0.** 아래 §4 참조 |
| `sourceRow` `sourceTab` `fromSheet` | 시트에서 온 자취. **옮기는 동안만** 쓰고 원장에는 안 남긴다 (대조가 끝나면 뗀다) |
| `createdAt` `updatedAt` `stateAt` | 기계 시각. 우리 저장소가 자기 것을 찍는다 |
| `supplierMemo` `channelMemo` | ★PII 섞일 수 있다. 역할용 API 로 안 나가게 **따로** 둔다 |

## 4. ★**칸은 있는데 아무도 안 채운 것** — 이게 지금 위험한 자리

| 칸 | 켜진 줄 | 뜻 |
|---|---|---|
| `collected` / `collectedAmt` | **0 / 461** | **수금이 한 줄도 안 적혀 있다.** 청구는 320건 했다 |
| `paid` / `paidAmt` | **0 / 461** | 지급 실행이 한 줄도 없다 |
| `supplierOk` | **0 / 461** | 공급사 확인이 0건 |
| `channelOk` | 38 / 461 | 영업채널만 조금 확인했다 |

★수금 칸이 생긴 까닭이 **「우리캐피탈이 10,403,278 을 이미 수금했는데 적을 칸이 없어 청구서를 한 번 더 만들 뻔했다」** 였다.
칸은 생겼고 **아직 아무도 안 채웠다.** 이중청구 위험이 그대로 있다.

그래서 우리 화면은 이 넷을 **「0건」이 아니라 「아직 안 씀」으로 말해야 한다.**

## 5. 그래서 우리 실적 한 줄

```
실적  { 실적번호 · ★차량번호 · ★접수일          ← 열쇠
        고객 · 공급사 · 영업채널 · 영업담당자 · 모델명
        상품구분 · 렌트구분 · 계약기간 · 렌탈료 · 보증금 · 차량가액 · 분납여부 · 계약형태
        계약서 · 인도(완료·일) · 취소 · 청구(여부·월·시각) · 계산서(발행·일자·사업자)
        청구단계 · 지급단계
        ★수수료  { 공급사: {mode, value}, 영업채널: {mode, value} }   ← 비율/정액을 갈라 담는다
        청구금액(null 가능) · 지급금액 · 인센티브 둘 · 가감 둘 + 사유
        정산대상 · 정산비율 · 부가세포함 · 이월(금액·달·사유)
        수금 · 지급 · 공급사확인 · 채널확인            ← ★전부 「아직 안 씀」
        원문 { note · settleNote · carryNote }        ← 글은 글로 남긴다
      }
```

## 6. 옮길 때 지킬 것

1. **읽은 줄 = 실은 줄 + 보류한 줄.** 조용히 사라지는 줄 0
2. **빈칸을 0 으로 만들지 않는다** — 「미확인」·「0」·「불가」는 서로 다른 사실이다
3. **요율/정액 판정을 줄에 남긴다** — 나중에 「왜 이렇게 읽었나」를 되짚어야 한다
4. **글자 칸을 버리지 않는다** — 뜻이 안 굳은 말이 거기 있다
5. **두 번 돌려도 같다**(멱등)
