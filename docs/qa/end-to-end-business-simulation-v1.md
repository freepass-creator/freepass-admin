# 1. 공급사 원문 → 상품화

## SIM-SUP-01 공급사 원문 수집
**관리자 메뉴**: `공급사 관리 > 원천 연결`

**버튼**
- `원문 가져오기`
- `최근 수집 보기`
- `매핑 검수`

**동작**
1. 승인된 Source Contract 기준으로 RAW snapshot 생성.
2. 기존 ERP fallback 금지.
3. 수집 성공/부분실패/실패를 구분.
4. 수집 성공만으로 상품 공개하지 않음.

## SIM-SUP-02 신규 표현 검수
원문: `카드 결제 O / 수수료 별도`

**화면**
- LEFT: 원문/문맥
- CENTER: 기존 매핑 후보
- RIGHT: Canonical 후보

**버튼**
- `이 상품만 적용`
- `이 출처의 같은 표현에 적용`
- `보류`

**기대**
- `CARD_PAYMENT=true`
- 수수료 숫자가 없으면 `CARD_FEE` 미확인
- `카드 가능 = 수수료 0%`로 만들지 않음

## SIM-SUP-03 차종 부분매칭
원문: `현대 쏘나타`

**기대**
- 모델=쏘나타까지만 확정
- 제조사/원산지는 마스터 관계로 파생
- 세부모델/트림 추측 금지

**상태표시**: `모델 매칭 · 하위정보 미확인`

## SIM-SUP-04 검수 완료 → 상품 공개
**버튼**: `Canonical 확정`

**조건**
- 검색/노출 필수값 검증 통과
- 핵심 충돌 없음

**결과**
- Product Version 생성
- Search Index/읽기모델 갱신
- ADMIN/SALES/WHITE LABEL에서 공통 상품으로 사용 가능

# 2. 관리자 상품검색 → 상세

## SIM-ADM-01 상품 찾기
**LEFT 패널**
- 검색창
- 빠른필터
- 상세필터

**주요 버튼/필터**
- 모델
- 기간
- 월대여료
- 보증금
- 연간주행거리
- 정책(21세, 카드, 후불, 분납 등)
- `필터 초기화`
- `상세필터`

**기대**
- 동일 Offer가 모든 계약조건을 만족해야 정확결과.
- 결과카드에는 검색에 일치한 Offer 가격 표시.

## SIM-ADM-02 목록 카드 클릭
**동작**
- CENTER만 선택 상품 상세로 변경
- RIGHT가 접수목록이면 그대로 유지
- matched offer 유지

## SIM-ADM-03 상품상세
**CENTER**
- 요약 / 상세정보
- 사진
- 모델정보
- 필요한 제원/실차정보
- Offer 선택
- 정책 배지

**핵심 버튼**
- `공유`
- `이 상품으로 접수하기`

불필요한 원천 메타는 기본 노출 금지.

# 3. 상품 → 접수

## SIM-APP-01 `이 상품으로 접수하기`
**화면 변화**
- LEFT 유지
- CENTER 유지
- RIGHT만 `신규접수`로 전환

**접수폼 최소 필드**
- 차량/Offer: 자동입력
- 영업채널
- 담당자
- 고객명
- 기타 확정 필드는 최신 결정에 따름

**버튼**
- `목록으로`
- `접수 저장`

## SIM-APP-02 접수 중 다른 상품 탐색
관리자가 LEFT에서 다른 상품을 클릭.

**기대**
- CENTER는 다른 상품을 볼 수 있음
- RIGHT Draft는 기존 접수상품 유지

**추가 버튼**
- `현재 상품으로 접수 변경`

누르면 변경 전/후 상품+Offer 비교 모달/영역 제공 후 확정.

## SIM-APP-03 저장 직전 상품조건 변경
공급사 갱신으로 92만원 → 95만원.

**저장 버튼 클릭 시**
- `조건 변경됨` 표시
- 이전 Draft / 최신 Offer 비교

**버튼**
- `최신 조건으로 변경`
- `접수 중단`

조용히 가격을 바꾸거나 예전 가격으로 신규접수 확정 금지.

## SIM-APP-04 접수 저장
**서버 동작**
- idempotency/submission id 확인
- Application Snapshot 생성
- productVersion/offer/policy 보존

**화면 결과**
- `접수 완료`
- 접수번호
- `접수상세 보기`
- `접수목록으로`

# 4. 접수 모니터링

## SIM-OPS-01 접수목록
**RIGHT 또는 접수관리 메뉴 목록**

한 행/카드에서 보여줄 것:
- 접수번호/접수일
- 고객명
- 차량
- 계약서
- 필수서류
- 인도
- 취소

**버튼/조작**
- 검색
- 상태필터
- 더블클릭/행 클릭 → `접수상세`
- `+ 신규접수`

## SIM-OPS-02 접수상세
**보여줄 것**
- 고객/영업채널/담당자
- 접수 당시 상품조건 Snapshot
- 현재 상품조건과 다르면 참고 표시

**체크/버튼**
- `계약서 완료`
- `필수서류 완료`
- `인도 완료`
- `접수 취소`
- `변경이력`

## SIM-OPS-03 인도완료
`인도 완료`를 체크하면:

1. Application delivery fact 저장
2. Performance 후보 생성
3. `실적 관리에서 보기` 링크 노출

실적 중복생성 금지.

## SIM-OPS-04 취소
**버튼**: `접수 취소`

**필수**
- 취소사유

**결과**
- Application=CANCELLED
- 실적 미생성 또는 기존 실적이 있으면 별도 취소/조정 플로우
- 원거래 삭제 금지

# 5. 실적 관리

## SIM-PERF-01 인도완료 실적 목록
**메뉴**: `실적 관리`

행에서 보여줄 것:
- 인도일
- 고객/차량
- 공급사
- 영업채널/담당자
- 받을 예정액
- 줄 예정액
- 영업자 확인 상태
- 공급사 확인 상태
- 이견 여부

**버튼**
- `영업자 확인 요청`
- `공급사 확인`
- `실적 상세`

## SIM-PERF-02 영업자 우선 확인
영업자 화면에서 자기 실적 확인.

**버튼**
- `확인`
- `이견 있음`

이견 입력 시 사유/요청금액/근거 기록.

## SIM-PERF-03 공급사 Cross Check
영업자 확인 후 관리자/공급사 단계.

**버튼**
- `공급사 확인 완료`
- `이슈 등록`

이슈 예:
- 해당 실적 불인정
- 공급금액 다름
- 지급기준 다름

## SIM-PERF-04 공급사 이슈 → 영업자 재확인
이슈가 영업자 지급/실적에 영향을 주면:

**버튼**
- `영업자 재확인 요청`

영업자에게:
- 기존 확인값
- 공급사 주장
- 변경 예상값

**버튼**
- `수용`
- `이견 유지`

## SIM-PERF-05 최종 확정
양측 검토가 끝난 건만:

**버튼**: `정산 확정`

**결과**
- Supplier Receivable 확정
- Channel Payable 확정
- Margin 계산 가능
- 금액 version/audit 기록

필터:
- 공급사

- 최종확정 여부

**버튼**
- `청구서 생성`

## SIM-SET-02 수금
공급사 청구 후 실제 입금.

**필드**
- 청구액
- 수금액
- 미수액

**버튼**
- `수금 등록`
- `수금 내역`

부분수금 허용.

## SIM-SET-03 영업채널 지급
**메뉴**: `정산 관리 > 지급`

- 영업채널
- 확정 지급액
- 실제 지급액
- 미지급액

**버튼**
- `지급 등록`
- `지급 보류`
- `내역 보기`

공급사 수금과 채널지급을 하나의 상태로 묶지 않음.

## SIM-SET-04 마진
**계산**
`실제 확정 받을액 - 실제 확정 줄액 = FreePass Margin`

# 9. 필수 예외 시뮬레이션

- 공급사 수집 실패 ≠ 상품 삭제
- 보증금 공란 ≠ 무보증
- 부분 차종 ≠ 완전 트림
- 다른 Offer의 조건 합성 금지
- 접수 저장 이중클릭 → 1건만
- 접수 후 현재 상품 변경 → Snapshot 유지
- 인도완료 정정 → 이력 필요
- 취소 후 원거래 삭제 금지
- 공급사 일부 실적 부인 → 정상건까지 막지 않음
- 부분수금 → 미수 잔액 유지
- 일부지급 → 미지급 잔액 유지
- 다른 영업채널 데이터/마진 노출 금지

# 10. Work 구현 원칙

각 버튼은 반드시 다음 4개가 정의되어야 한다.

1. **누가 누를 수 있는가**
2. **누르기 전 필요한 조건은 무엇인가**
3. **누르면 어떤 데이터가 생성/변경되는가**
4. **성공 후 다음 화면/업무는 무엇인가**

화면에 버튼만 있고 뒤 상태변화가 정의되지 않으면 구현 완료가 아니다.
