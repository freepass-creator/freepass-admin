# FreePass Admin UI 작업 — 10점을 위한 남은 한 가지: 실제 화면 검증

검토 대상: `claude/erp-platform-ui-ux-hvfyfa` 브랜치의 규격통일 작업(테두리 제거 → 표면 위계 →
타이포/간격 정규화 → 아이콘/터치 → 키보드/a11y → 폼 검증 → 위험 액션 구분)
평가: 대표 2026-09-24 「작업 점수는 몇 점?」→ **8점**. 설계·범위·문서화(`docs:`+`ui:` 짝)는
이미 잘하고 있다. 10점이 되려면 이 한 가지만 닫으면 된다.

---

## 0. 결론

**코드만 보고 커밋하지 말고, 고칠 때마다 실제 브라우저 화면을 스크린샷으로 찍어서 눈으로 봐라.**

지금까지 같은 원인으로 회귀가 **두 번** 났다. 둘 다 코드 리뷰로는 안 틀려 보이는데,
렌더링해서 보면 글자가 안 보이는 종류였다 — 이런 건 스크린샷 없이는 못 잡는다.

---

## 1. 실제로 났던 사고 — 증거

### 사고 1. 선택된 퀵필터 알약 글자가 안 보임

- 커밋: interaction-elevation 계열(2026-09-24)
- 증상: `/products`의 "전체 24" 알약(선택 상태, `aria-pressed="true"`)이 흰 배경에 흰 글자로 렌더링돼
  **글자가 안 보였다.**
- 원인: `sync-erp-standard.mjs`가 자동으로 넣는 `.erp-std a.erp-facet-opt[aria-pressed="true"] { color: ... }`
  (태그 한 단계 더 구체적)가, 새로 추가한 `.erp-std .erp-facet-opt[aria-pressed="true"] { color: white }`보다
  **specificity가 낮아서 조용히 졌다.**
- 코드만 보면 "흰 글자를 줬으니 됐다"로 보인다 — 실제로는 안 됐다.

### 사고 2. "접수하기" primary 버튼 + 선택된 퀵필터 알약이 한 번에 다시 안 보임

- 커밋: 카드/버튼 표면 위계 정규화 계열(2026-09-24)
- 증상: `/products` 상세 판의 "접수하기" 버튼과 "전체 24" 알약이 **또** 흰 배경에 흰 글자로 안 보였다.
- 원인:
  ```css
  .erp-std :is(
    .erp-btn:not(.erp-btn--ghost),   /* :not() 여러 개 — 무거운 가지 */
    .erp-facet-opt,                   /* 원래는 단순한 가지 */
    .erp-dd,
    .dz-fs-open
  ) { background-color: var(--fp-surface-soft); }
  ```
  `:is()`의 specificity는 **목록 전체가 아니라 그 안에서 가장 무거운 가지 하나** 기준으로 정해진다.
  `.erp-facet-opt`는 원래 단순한데, `.erp-btn:not(...):not(...):not(...)`와 **같은 `:is()`에 묶여** 있다는
  이유만으로 specificity가 같이 올라가서, 훨씬 나중에 정의된 "선택 상태" 규칙(`.erp-facet-opt[aria-pressed="true"]`)
  까지 덮어썼다.
- 이건 특히 위험한 패턴이다 — **`.erp-facet-opt` 코드는 한 글자도 안 바뀌었는데, `.erp-btn` 쪽에 `:not()`을
  하나 더 추가했다는 이유만으로 `.erp-facet-opt`가 깨진다.** 코드 diff만 봐서는 왜 깨졌는지 절대 못 찾는다.

두 사고 모두 Claude가 `/products`, `/settlement`, `/esign` 화면을 실제로 스크린샷 찍어서 발견하고 고쳤다
(커밋 `61c0a09` 등). 원 작업자가 스크린샷을 찍어봤다면 커밋 전에 스스로 잡았을 문제다.

---

## 2. 왜 이게 10점을 막는 유일한 지점인가

- 설계 방향, 커버 범위(a11y·키보드·폼·아이콘·위험 액션), 문서화 습관은 이미 충분히 좋다.
- 남은 리스크는 딱 하나 — **"코드는 맞는데 화면은 틀린" 종류의 버그를 스스로 못 잡는다**는 것.
  이 프로젝트는 색상 대비·선택 상태 표시가 핵심인 미니멀 디자인이라, 이 종류의 버그가 특히 잘 난다
  (테두리를 없앨수록 배경색 하나로 상태를 표현해야 하고, 그 배경색이 깨지면 바로 "안 보임"으로 이어진다).

## 3. 앞으로 지켜야 할 것 — 커밋 전 체크리스트

1. **CSS의 배경색/글자색/테두리 색을 바꾸는 커밋은, 그 규칙이 실제로 걸리는 화면을 반드시 스크린샷으로 찍는다.**
   최소 대상: `/products`(선택된 알약 + primary 버튼이 다 있는 화면), 그리고 바꾼 클래스가 쓰이는 다른 화면 1곳.
2. **선택 상태(`[aria-pressed="true"]`, `[aria-current="true"]`)가 있는 요소는 특히 주의한다** — 기본 상태만
   스크린샷 찍고 끝내지 말고, 그 요소를 실제로 선택한 화면도 찍는다.
3. **`:is()`/`:where()` 안에 여러 선택자를 묶을 때, 하나라도 `:not()`을 3개 이상 갖고 있으면 분리한다.**
   `:is()`의 specificity는 가장 무거운 가지를 따라간다는 걸 기억한다 — 무거운 조건은 별도 규칙으로 뺀다.
4. **`sync-erp-standard.mjs`가 자동으로 넣는 `.erp-std a.erp-*[...]` 링크색 리셋 규칙과 specificity가
   부딪히지 않는지 확인한다** — `scripts/sync-erp-standard.mjs` 상단 하드코딩 목록을 먼저 훑어본다.
5. 스크린샷은 Playwright + `/opt/pw-browsers/chromium`로 뜬다(이 세션에서 Claude가 쓰던 방식과 동일):
   ```
   NODE_PATH=/opt/node22/lib/node_modules node shot.cjs "http://localhost:<port>/<route>" out.png 1440 900
   ```
6. 위 체크를 거친 뒤에도 `tsc --noEmit` · `npm test` · `next build`는 지금처럼 계속 돌린다 — 그건 이미 잘하고 있다.
