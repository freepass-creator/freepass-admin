## 1. ★축이 «둘» 이다 — 섞으면 둘 다 못 읽는다

`esign-progress.ts` 머리 주석이 그대로 못박아 뒀다:

> 「`/contract` 의 5단계와 **축이 다르다**. 저기(`contractStage`)는 **우리 일**이 어디까지인지,
> 여기는 **손님**이 서명 링크에서 어디까지 갔는지다. **둘을 한 축에 섞으면 둘 다 못 읽는다.**」

### 축 ① 관리자가 보는 것 — `EsignCenterStage` 다섯

정본: `ESIGN_SEND_CENTER_REDESIGN_2026-08-19.md §2-1`

| | 단계 | 들어오는 조건 | **이 단계의 «유일한» 행동** | 나가는 조건 |
|---|---|---|---|---|
| ① | **작성** | 새 계약 만들기 (저장 전 draft) | 공급사·계약서·정책 → 차량 → 대여조건 → **계약서 만들기** | 저장 성공 |
| ② | **발송 전** | `sign_status ∈ {미발송, 발행}` | A4 확인 → **링크 만들기** → **링크 복사**·전달 | 고객이 엶 |
| ③ | **고객 작성 중** | `∈ {열람, 진행중}` · 보완 요청 뒤 재작성 포함 | **없다(기다린다).** 재전달용 복사·해지만 | 고객 제출 |
| ④ | **검토 대기** | `session ∈ {pending_review, approving, rejecting}` | 제출물 확인 → **승인** 또는 **보완 요청** | 승인 → ⑤ / 보완 → ③ |
| ⑤ | **완료** | `sign_status === '서명완료'` | 완료 PDF · **봉인 검증** · 인도일 확정 | — |

- **목록 뱃지 = 상단 스테퍼 = 필터 칩 = 이력 라벨 — 전부 이 표의 이름.** 다른 번호·다른 이름 금지
- 원문자(①②③)는 **스테퍼에만**. 카드 안에는 번호를 안 쓴다
- 판정 우선순위: **완료 > 검토 대기 > 고객 작성 중 > 발송 전**
- ★③ 「고객 작성 중」의 행동이 **없다** — 기다리는 단계다. 이걸 화면이 정직하게 말해야 한다

### 축 ② 손님이 가는 길 — `ESIGN_STEPS` 여덟

```
본인확인 → 본인정보 → 차량정보 → 대여조건 → 보험 → 서류제출 → 약관동의 → 서명
```

- 목록의 **`4/8`** 이 이 값이다(`done / total`)
- 상태 일곱: `미발송 · 발행 · 열람 · 진행중 · 서명완료 · 반려 · 만료`
- 색 다섯: `gray · blue · amber · green · red`
- ★판정 우선순위가 중요하다 — **끝난 것·막힌 것을 먼저** 본다.
  서명완료된 계약이 만료일 넘겼다고 「만료」로 보이면 안 된다
- 착한거래가 `esign_progress`(0~8)를 직접 주면 **그걸 믿는다** — 우리가 모르는 단계까지 센다
- 통과 판정: `sign_consents` 의 키 집합. **값이 0·false·빈문자면 «아직»** 이다.
  키가 있다고 통과로 세면 안 된다

## 2. 플래그는 단계와 «섞지 않는다»

| 플래그 | 조건 | 표시 |
|---|---|---|
| **확인 필요** | BLOCK 체크 1개↑ | 목록 행 뱃지 옆 **빨간 점** + 작업면 「발송 전 확인」 카드(문제 있을 때만) |
| **만료 / 해지** | `expiresAt ≤ now`(미제출) / `revokedAt` | ②·③ 카드가 **「링크 다시 만들기」** 카드로 바뀜 |
| **보완 요청됨** | `sign_status === '반려'` | ③ 단계 + 카드 상단에 요청 항목·사유·**횟수** |

> ★「확인필요」는 **더 이상 버킷이 아니다.** — 「목록 5건 중 4건이 빨갛던 문제의 해법」

필터 칩: `전체 · 발송 전 · 고객 작성 중 · 검토 대기 · 완료 · 확인 필요(플래그)`

## 3. 발송 전 검사 — `EsignCheck`

```ts
level: 'PASS' | 'WARNING' | 'BLOCK'
```
**BLOCK 이면 발송을 막는다.** 정책 등급으로 발행 가능 여부를 보고(`canIssueContract`),
대여료·운전연령·주행거리 옵션이 정책과 맞는지 검증한다(`esign-vehicle-selection`).

★공급사 정보가 비면 「발송 전 확인」 아래에 **「파트너사관리에서 {공급사} 정보 입력」** 버튼이 뜬다.
