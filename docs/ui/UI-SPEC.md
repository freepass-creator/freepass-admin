# UI 규격 — freepass-admin

## 0. 실제 앱 정본 — 2026-09-18

> 아래 기존 mockup 규격은 설계 이력으로 유지한다. **값이 다르면 이 절과 실제 `src/app` 구현이 우선**한다.
> 실제 구현 정본: `src/app/globals.css` + `src/app/_design/*` + 각 route workspace.

### 현재 화면 체계

- Desktop 상단 업무축: **상품찾기 / 계약접수 / 정산관리 / 전자계약**
- Mobile depth 0 하단축: **상품 / 접수 / 계약 / 청구 / 지급**
  - 청구·지급은 같은 정산관리 화면의 서로 다른 입구다.
  - 상세(depth 1·2)에서는 5탭 대신 해당 판의 하단 action bar가 선다.
- 첫 화면: `/` → `/intake`
- 실제 route: `/products` · `/intake` · `/settlement` · `/esign`

### 현재 시각 토큰

### 판 규칙

- 상품찾기: 상품 목록 **2/3** + 상품 상세 **1/3**
- 계약접수: 상품 목록 + 상품 상세 + 접수/업무 판
- 정산관리: 묶음 + 실적 줄 + 접수 상세
- 전자계약: 계약 목록 **2/3** + 계약 상세 **1/3**
- 모바일에서는 같은 내용을 압축하지 않고 **목록 → 상세** depth로 전환한다.

### 구현 원칙

1. 목록은 `_design/ListRow`를 우선 사용한다.
2. 뱃지는 `_design/Badges`를 사용한다.
3. 아이콘은 `_design/Icon` 한 벌을 쓴다.
4. 관리자 chrome은 `_design/AdminChrome`, 폰 하단은 `_design/MobileTabBar`가 정본이다.
5. mockup 전용 `admin-shell.*`과 실제 route가 다르면 실제 route를 고친다. mockup을 운영 화면으로 간주하지 않는다.
6. 새 UI 규격을 만들기 전에 `globals.css`의 확정 토큰과 이 절을 먼저 확인한다.

## 5. 판 짜임 — 넷 칸, 칸마다 «맡은 일» 이 하나

```
┌──────────────────────────────────────────────────┐
│ 제목 · 딸린 수      (빈칸)      이 판에 거는 행동 │ .ph  38   무엇을 보는가
├──────────────────────────────────────────────────┤
│ [⌕ 찾는 칸 318 ····· ✕ │ 세부필터 2]  걸린 조건… │ .bar 38   무엇을 고르는가
├──────────────────────────────────────────────────┤
│                                                  │
│  표 (줄 34 · 머리 30 · 머리 고정)                 │ .pb  남는 만큼
│                                                  │
├──────────────────────────────────────────────────┤
│ 조건 밖 0   확인 필요 2      (빈칸)    마진 합계 … │ .pf  30   무엇이 남았나
└──────────────────────────────────────────────────┘
```

★**칸을 섞지 않는다.** 이 하나만 지키면 판 여덟 개가 저절로 같아진다.

| 칸 | 넣는 것 | **넣지 않는 것** |
|---|---|---|
| `.ph` 38 | 제목 · 딸린 수 · 이 판 «전체» 에 거는 행동(오른쪽, 최대 둘) | 찾기 · 필터 · 셈 |
| `.bar` 38 | **찾는 칸 하나** + 갈래 단추 + 걸린 조건 딱지 | 실행 단추 |
| `.pb` | 표 · 상세 · 빈 상태 | — |
| `.pf` 30 | **셈만** — 라벨 + 숫자 | ★**설명문 · 훈계 · 도움말** |

- `.bar` 는 고를 게 없으면 **띠째로 없앤다**. 빈 띠를 남기지 않는다
- `.pf` 높이는 `ctl 30` 이다 — «읽기만» 하는 띠라 `act 38` 을 안 쓴다
- ★`.pf` 에 설명을 쓰지 않는 까닭: **매일 여덟 시간 보는 사람에게 설명은 소음**이다.
  한 번 읽으면 그 뒤로는 자리만 먹는다. 규칙은 이 문서에 적고, 화면에는 **셈**을 둔다

### 5-1. ★셈(`.pf`) 규격

```
<span class="t"><i>라벨</i><b class="warn">2</b></span>
```

- 왼쪽부터 **눈여겨볼 것 → 평범한 것** 차례. 오른쪽 `.sp` 뒤는 합계나 판 행동
- 숫자는 고정폭(`tabular-nums`) — 값이 바뀌어도 자리가 안 흔들린다
- 색은 뜻이 있을 때만: `warn` 손이 가야 할 것 · `bad` 틀어진 것 · `ok` 끝난 것
- ★**0 은 눌러 둔다**(`.z` — 회색·보통 굵기). **없는 것이 눈을 끌면 안 된다**

| 판 | 셈 |
|---|---|
| 상품 목록 | 조건 밖 · 확인 필요 |
| 접수 목록 | 칠 것 · 인도완료 · 취소 |
| 실적 목록 | 정상 · 환수 · 이슈 ⟶ 마진 합계 |
| 청구 원장 | 공급사 · 미수 ⟶ 미수 합계 |
| 지급 원장 | 영업채널 · 미지급 · 보류 ⟶ 미지급 합계 |
| 계약 목록 | 서명 완료 · 고객 작성 중 · 발송 전 · 확인 필요 |

### 5-2. ★찾는 칸(`.fd`) — 하나로 끝낸다

```
┌─────────────────────────────────────────────┐
│ ⌕  싼타페 36개월 무보증              ✕ │ 세부필터 2 │   318 × 30
└─────────────────────────────────────────────┘
      돋보기      친 말              지움  칸 안의 필터
```

- **폭 318** (1400 아래에서 268). 세부필터가 약 84 를 먹으므로 친 말에 남는 자리가 ~200
- ★`type="text"` 다. **`type="search"` 로 두면 브라우저가 ✕ 를 «또» 그려 두 개가 된다**
- ✕ 는 **친 말이 있을 때만** 나온다
- **세부필터는 칸 «안» 에 산다** — 검색어로 못 자르는 것을 자르는, 같은 일이라서다.
  걸린 게 있으면 단추가 채워지고(`--key`) 옆에 수가 붙는다
- 걸린 조건 **딱지는 칸 밖** `.bar` 에 — 「무엇을 고르는 도구」와 「지금 걸린 것」은 다른 물건이다
- 돋보기는 **SVG** 다. 글리프(`⚲`)는 브라우저가 이모지로 그려 색이 튄다

## 6. 단추 — 자리로 말한다

```
┌──────────────────────────────────────┐
│ 메모 입력칸                    (30)    │
│ [⋯] [보조]        (빈칸)     [■ 주]   │  38
└──────────────────────────────────────┘
```

- **주 행동은 하나**만 채운 색(`--key`). 지금 단계에 따라 글자가 바뀐다
- **보조**는 테두리만
- ★**위험한 것은 색이 아니라 «자리»로 뗀다** — 취소·삭제는 `⋯` 안에만 둔다.
  빨간 단추를 늘 띄워 두면 매일 보는 사람은 그걸 곧 무시한다
- 주 단추 최소 폭 **136**

### ★대비 바닥선 — 4.5:1

> 대표(2026-09-16): 「**뭔가 회색으로 눈에 안 들어와**」

까닭은 **바탕이 아니라 글자**였다. 예전 `--ink-3`(`#8a939b`)이 **3.1:1** 인데
표의 차량·공급사·채널이 죄 그 색이라 «본문 절반이 가라앉았다».

- 부드러움은 **바탕(미색)·채도(낮춤)·여백**으로 사고, **글자 대비는 안 판다**
- 회색 세 단은 «덜 중요해서» 가 아니라 **«읽는 차례»** 다 — 셋 다 읽히는 값이어야 한다

표에 딱지 스무 개가 파스텔로 깔리면 정작 봐야 할 「이슈」가 안 보인다.

★**고른 줄**은 아주 옅은 틴트 + **왼쪽 3px 막대**로만 말한다(레트로가 쓰던 방식).

## 9. 폰 — 한 단 크게, 그러나 **같은 자리**

| 토큰 | 값 |
|---|---|
| `--m-bar` | **52** 앱바 |
| `--m-ctl` | **38** 입력칸·아이콘 단추 |
| `--m-row` | **64** 목록 한 줄 (손가락) |
| `--m-act` | **44** 실행 단추 |

★**PC 의 판 셋을 «압축»하지 않는다.** 폰은 **페이지가 바뀐다**:

```
목록 ──▶ 상세 ──▶ 접수폼 ──(저장)──▶ 접수목록
 ◀── 뒤로 ──┘
```

- 위: `← 뒤로 · 제목/부제 · 우측 액션` (목록에서는 뒤로가 없다)
- 아래: 탭 **넷** — `상품 · 접수 · 실적 · 설정` + 배지, `safe-area` 여백
- 실행 띠는 **탭바 위**에 붙는다
- ★Offer 고르기는 표가 아니라 **큰 카드 단추** — 폰에서 표는 못 누른다

### 9-1. 페이지 수

지금 **8장** + 시트 1

| 탭 | 페이지 |
|---|---|
| 상품 | 상품목록 · 상품상세 · 신규접수 |
| 접수 | 접수목록 · 접수상세 |
| 실적 | 실적목록 · 실적상세 |
| 설정 | 설정 |
| (시트) | 세부필터 |

아직 안 만든 것 **6장** — 청구목록/상세 · 지급목록/상세 · 전자계약목록/상세.
**다 하면 15장**이고 그중 11장이 「목록↔상세」 쌍이라 한 틀로 찍어낸다.

## 10. 재는 법
