# freepass-admin — Product Experience Principles

작성일: 2026-09-13
상태: USER DIRECTION CONFIRMED / Work·AI 공통 UI·UX 판단 기준

## 목적

freepass-admin의 화면은 단순히 보기 좋은 ERP가 아니라 아래 네 조건을 동시에 만족해야 한다.

1. **직원이 일하기 편해야 한다.**
2. **외부에 보여줘도 정돈되고 신뢰감 있어야 한다.**
3. **PC에서 모바일로 자연스럽게 전환되어야 한다.**
4. **현재의 웹/앱 UI 문법에 맞되 유행성 장식을 남발하지 않는다.**

이 네 조건 중 하나라도 크게 깨지면 시안 완료로 보지 않는다.

---

## 1. Employee-first

직원이 매일 반복해서 쓰는 업무 화면이므로 예쁜 카드보다 업무 속도를 우선한다.

- 첫 화면에서 `어디서 찾고 / 무엇을 확인하고 / 어디서 처리하는지`가 바로 보여야 한다.
- 같은 업무를 처리하기 위해 화면을 여러 번 왕복하지 않는다.
- 자주 보는 값은 처음부터 보이고, 드물게 보는 원문·메타·진단값은 접기/상세로 보낸다.
- 검색·필터·선택·스크롤·작성 중 Draft를 가능한 한 보존한다.
- 버튼은 현재 단계의 실제 행동을 표현한다. 추상적인 `진행`, `처리`보다 `접수 저장`, `인도 완료`, `수금 등록`처럼 업무 언어를 사용한다.
- 목록에서는 스캔 속도를 우선하고, 상세에서는 판단 근거를, 업무패널에서는 실행에 필요한 입력만 보여준다.
- 한 화면에서 중요한 행동은 한두 개만 강하게 보이게 한다.
- 내부 사용자가 자주 틀리는 동작은 UI에서 예방한다. 예: 접수 Draft 중 다른 상품 탐색이 접수상품을 자동 변경하지 않음.

핵심 문법:

`LIST = 찾기 / DETAIL = 확인 / WORK = 실행`

---

## 2. Clean enough to show outside

내부 ERP라도 공급사·투자자·파트너에게 보여줬을 때 임시 관리툴처럼 보이면 안 된다.

- 브랜드와 제품 위계가 분명한 단정한 화면을 사용한다.
- 흰 작업면, 충분한 여백, 일정한 타이포그래피, 얇은 구분선을 기본으로 한다.
- 불필요한 대형 카드, 과한 그림자, 알약형 상태 남발, 의미 없는 그래픽을 피한다.
- 숫자·금액·상태·차량명 정렬을 일관되게 유지한다.
- 상태색은 의미가 있을 때만 사용한다. 색만으로 상태를 전달하지 않는다.
- 데모용 가짜 정보나 실제 업무에 없는 장식을 넣지 않는다.
- 화면을 캡처해 외부에 보여줘도 무엇을 하는 시스템인지 자연스럽게 이해돼야 한다.

목표 인상은 `화려하다`보다 **`깔끔하다 / 잘 정리됐다 / 일하기 좋아 보인다`**이다.

---

## 3. Mobile-ready by structure, not by shrinking

모바일화는 PC 화면을 작게 축소하는 작업이 아니다. 처음부터 정보구조를 분리해서 설계한다.

Desktop:

`상품목록 1/3 | 상품상세 1/3 | 업무패널 1/3`

Mobile:

`LIST → DETAIL → WORK`

원칙:
- Desktop 3열을 모바일에서 가로로 욱여넣지 않는다.
- 같은 데이터와 업무상태를 사용하되 한 화면에 하나의 주 목적을 둔다.
- 모바일 주요 조작영역은 최소 44px 수준을 목표로 한다.
- 검색/입력은 충분한 높이와 읽을 수 있는 글자 크기를 유지한다.
- 뒤로가기 시 검색어, 필터, 스크롤, 선택, Draft를 복원한다.
- Desktop에서 hover/double-click만 가능한 기능에는 모바일 대체 동작을 둔다.
- 모바일 때문에 별도 데이터 모델이나 별도 업무 로직을 만들지 않는다.

즉 **Responsive UI는 달라도 Domain Contract는 하나**다.

---

## 4. Modern, but not fashion-driven

최신 트렌드는 유행하는 모양을 복사한다는 의미가 아니다.

채택할 것:
- 명확한 정보 위계
- 큰 상단 장식보다 콘텐츠 우선
- 빠른 검색과 즉시 필터
- 자연스러운 inline 상태 표시
- full-row click/tap
- sticky action이 필요한 곳의 명확한 주 행동
- 적절한 whitespace
- subtle background highlight
- responsive single-task mobile flow
- loading / empty / error / saving / stale state를 실제 UI로 설계

피할 것:
- 이유 없는 glassmorphism
- 카드 안에 카드 반복
- 모든 값을 badge/chip으로 표현
- 지나치게 둥근 모서리
- 무거운 고정 상단바
- 장식용 대형 차 이미지
- 업무보다 애니메이션이 먼저 보이는 인터랙션
- 모바일에서 정보가 사라지는 단순 hide 방식

트렌드 적용 여부는 `직원 업무속도 + 가독성 + 반응형 + 유지보수성`을 개선하는지로 판단한다.

## 5. Atomic data projection

ERP4에서 축적한 원자 철학을 참고하되 v1은 독립 프로젝트다.

화면에는 데이터베이스의 모든 필드를 보여주지 않는다.

- 목록: 선택/검색에 필요한 원자
- 상세: 계약 판단에 필요한 원자
- 업무: 현재 행동에 필요한 원자
- 진단: 원문·source·mapping·검수 메타

새 필드가 생겼다고 자동으로 UI에 한 줄 추가하지 않는다. 먼저 어느 사용자에게 어느 단계에서 필요한지 판단한다.

같은 Canonical 데이터가 ADMIN / SALES / WHITE LABEL에서 역할에 맞게 projection된다. 화면별로 상품의 의미를 다시 계산하지 않는다.

---

## 6. Component / behavior reuse

직원 편의와 모바일화를 동시에 달성하려면 시각 재사용보다 **동작 재사용**이 중요하다.

공통화 대상:
- Search state
- Filter state
- Product selection
- matched Offer
- Product detail projection
- Application Draft
- Application Snapshot
- status/action rules

PC와 모바일은 같은 컴포넌트를 무조건 그대로 렌더링하는 것이 목적이 아니다. 같은 Domain/State를 서로 적합한 Layout Component로 표현한다.

---

## 7. UI 시안 검수 질문

모든 주요 시안은 구현 전 아래 질문에 답한다.

### 직원 업무
- 직원이 첫 5초 안에 다음 행동을 찾을 수 있는가?
- 하루 50~100번 반복해도 불필요한 클릭이 없는가?
- 목록만 훑어도 어떤 건을 열어야 할지 알 수 있는가?
- 실수했을 때 되돌리거나 이력을 확인할 수 있는가?

### 정보
- 화면에 보이는 값은 실제 원자/Canonical 데이터인가?
- 데이터에 있다는 이유만으로 불필요한 값이 노출되지 않았는가?
- 미확인과 0/불가가 구분되는가?
- 검색에서 선택한 Offer가 상세/접수까지 유지되는가?

### 표현
- 외부 파트너에게 화면을 보여줘도 임시툴처럼 보이지 않는가?
- 제목·본문·메타·숫자 위계가 일관적인가?
- 강조색이 너무 많은가?
- 카드/배지가 필요 이상으로 사용됐는가?

### 모바일
- 이 화면을 390px에서 한 가지 목적의 화면으로 설명할 수 있는가?
- 터치 대상이 충분히 큰가?
- 뒤로가기로 작업 맥락이 복원되는가?
- PC 전용 조작에 대한 대체 동작이 있는가?

### 유지보수
- 새 공급사/새 정책이 추가돼도 레이아웃을 다시 짜지 않아도 되는가?
- 새 화면을 만들지 않고 기존 UI 문법으로 해결 가능한가?
- 화면에서 별도 업무 규칙을 재구현하고 있지는 않은가?

---

## 8. Acceptance Gate

UI/UX는 아래 상태를 분리해서 보고한다.

- `FLOW DESIGNED`
- `IMAGE REVIEWED`
- `USER APPROVED`
- `CODED`
- `RESPONSIVE VERIFIED`
- `INTERACTION TESTED`
- `DEPLOYMENT VERIFIED`

정적 이미지가 깔끔하다는 이유만으로 `RESPONSIVE VERIFIED` 또는 `INTERACTION TESTED`로 보고하지 않는다.

---

## 한 문장

> freepass-admin의 좋은 UI는 화려한 화면이 아니라, 직원이 생각을 덜 하고 빠르게 일하며, 외부에 보여줘도 정돈돼 보이고, 같은 업무가 모바일에서도 자연스럽게 이어지는 화면이다.
