## 1. 최신 사용자 역할 지시

사용자는 ChatGPT를 검토 전용으로 제한하지 않고, 채팅에서 수행 가능한 작업도 실제로 분담하기를 요청했다. Work가 전체 구현·통합을 진행하는 동안 ChatGPT도 설계 보완, 테스트, 자료 규격, 독립 가능한 코드 수정을 수행한다.

공동 작업 원칙:
- GitHub가 코드·인수인계의 기준이다. 다른 세션이 이 대화를 자동으로 읽었다고 가정하지 않는다.
- 작업 시작 전에 대상 파일, 기준 커밋, 관련 PR과 규칙을 확인한다.
- 같은 파일을 동시에 고치지 않도록 범위를 기록한다. 문서상의 역할 분담 자체가 강제 잠금은 아니다.
- 보조 수정은 별도 브랜치/PR로 제출하고 main이나 운영 배포를 몰래 변경하지 않는다.
- 코드 작성 / 정적 검토 / 테스트 실행 / DB 검증 / 배포 검증을 구분한다.
- UI 변경은 먼저 실제 화면 시안을 확인하는 사용자 원칙을 유지한다. 이번 작업은 UI 변경이 아니다.
- 자동 백그라운드 작업이나 무한 사용을 전제로 하지 않는다. 각 작업의 실제 수행 결과를 남긴다.

## 2. 이번에 직접 확인한 근거

현재 저장소의 AGENTS.md, docs/MASTER-v1.md, Git 트리와 main ref, 열린 PR 목록, 공통 상품 및 접수 타입, create-application.ts를 읽었다. 읽은 시점에 열린 PR 조회 결과는 비어 있었다. 이 사실만으로 Work가 다른 환경에서 작업하지 않는다고 단정하지 않는다.

MASTER의 요구: 현재 상품이 바뀌어도 저장된 접수의 Offer/Policy 스냅샷은 바뀌지 않아야 한다.

기존 createApplication은 정책 객체를 `{ ...policy }`로 복사했지만 MULTI_SELECT의 `value: string[]`를 원본과 공유했다. Offer 정책과 상품 정책 두 곳에 같은 문제가 있다. 공유 배열을 제자리에서 변경하면 원본과 스냅샷이 서로 영향을 받을 수 있다.

이는 공통 함수의 참조 분리 결함이다. 실제 고객 데이터가 훼손됐다는 조사 결과가 아니며, 현재 관리자 UI가 이 공통 함수를 호출하는지에 대한 통합 검증도 이번 범위가 아니다.

## 4. 회귀 테스트 8개

1. 원본 Offer의 복수선택 배열을 바꿔도 접수값 보존.
2. 원본 상품의 복수선택 배열을 바꿔도 접수값 보존.
3. 접수 배열을 바꿔도 두 범위의 원본 상품값 보존.
4. 같은 상품에서 생성한 서로 다른 접수 간 배열 분리.
5. Boolean/Number/Money/Percentage/Single Select/Text/Date 값과 타입 보존.
6. 선택한 Offer의 기간·대여료·보증금 보존, 부분 모델의 하위값 추측 금지.
7. 다른 상품의 Offer ID 거절.
8. 생성 시 원본 불변, 미확인 보증금을 0으로 생성하지 않음, 최초 체크·시각 유지.

이번 세션에서는 코드 정적 검토와 GitHub 직접 작성만 수행했다. 위 테스트의 성공/실패를 실행 결과로 보고하지 않는다.

## 5. Work 실행 및 통합 절차

기존 package.json의 개발 의존성이 준비된 Node/TypeScript 검증 환경에서, 저장소 루트 기준:

```sh
npx --no-install tsc --project tests/tsconfig.snapshot.json
node --test tests/.snapshot-build/tests/domain/application-snapshot.test.js
```

첫 명령이 실패하면 다음 명령의 오래된 출력으로 통과를 보고하지 않는다. 단일 명령으로 실행하려면 두 명령을 `&&`로 연결한다. 새 테스트 패키지를 도입하지 않는다.

가능하면 동일 테스트를 원래 create-application.ts에도 적용해 참조공유 반례가 실패하는지 확인하고, 수정 버전에서 통과하는지 비교한다. 테스트 기대값을 버그 있는 구현에 맞춰 완화하지 않는다.

검증 후 실제 관리자 접수 흐름이 공통 도메인 함수를 사용하는지, DB 저장 후 재조회 및 상품 갱신 후 기존 접수 보존이 되는지는 별도로 확인한다. 이 PR만으로 실제 저장·중복방지·입력 검증·권한·감사기록까지 완성됐다고 보고하지 않는다.

## 6. 범위 밖 / 다음 협업 후보

원천 어댑터의 승인 샘플과 예상 검색 결과, 동일 Offer 검색 검수, 접수 초안과 상품 탐색 분리, 영구저장과 변경이력 등은 별도 작업 단위다. 이번 PR로 새로운 정책 정의·모델 계층·외부 연결·고객정보 수집 범위를 추가 승인하지 않는다.

원격 main 병합·운영 배포는 수행하지 않는다. 다음 담당자는 자신의 변경과 충돌 여부를 확인한 뒤 검증 증거를 PR에 남기고 통합한다.
