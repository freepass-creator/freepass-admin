# FreePass Admin ERP5 Persistence P3 — 2026-09-20

Status: `ADAPTER IMPLEMENTED / CREDENTIAL-BOUND / NO DEPLOYMENT CLAIM`

## 목적

Admin 핵심업무 P0/P1/P2의 Port를 실제 ERP5 Firestore에 연결할 수 있게 한다.

- 상품: 기존 ERP5 정본 컬렉션을 읽는다.
- 접수·실적·정산: 기존 컬렉션 이름을 추측해 덮지 않고 Admin 전용 namespace에 새로 쓴다.
- RTDB fallback은 없다.
- freepasserp4 credential fallback도 없다.

## 상품 read

정본 Firebase project:

`freepasserp5`

읽는 기존 컬렉션:

- `products`
- `policy`
- `vehicle_master`

변환 규칙:

- listable=false 제외
- price가 없거나 유효 Offer가 없으면 제외 이유를 센다
- 보증금 미확인은 0으로 바꾸지 않는다
- price key에서 기간/약정주행거리를 파싱한다
- policy의 협의/불가/제한없음 등을 boolean/0으로 추측하지 않는다
- 현재 vehicle_master에 다시 매칭하여 MODEL/SUB_MODEL/TRIM 깊이를 확정한다
- source timestamp/version을 Application stale-version guard에 쓰는 numeric version으로 보존한다

상품 Adapter는 read-only다.

## Admin write namespace

반드시 명시:

```
FPA_REPOSITORY_MODE=erp5
ERP5_ADMIN_NAMESPACE=freepass_admin_v1
ERP5_WRITE=on
```

생성되는 논리 컬렉션:

- `<namespace>_applications`
- `<namespace>_counters`
- `<namespace>_performances`
- `<namespace>_settlements`
- `<namespace>_billings`
- `<namespace>_ledger`

namespace가 없으면 write collection을 추측하지 않는다.

## 접수 transaction

`Erp5ApplicationRepository`:

- submissionId replay 확인
- 날짜별 counter read/update
- 사람이 읽는 접수번호 sequence 발번
- Application Snapshot과 history를 한 transaction으로 생성
- progress/cancel mutate도 Firestore transaction
- immutable snapshot/history 규칙 재검증

## 실적/정산 transaction

`Erp5OperationsRepository`:

- Application당 Performance 1건
- Performance FINALIZED + Settlement 생성 atomic
- Settlement당 Billing 1건
- Ledger append-only
- 기존 ledger 삭제/수정 금지
- reversal은 새 ledger entry로만 표현

## 보안 경계

Persistence를 연결했다고 Auth가 연결된 것이 아니다.

현재 production Actor/Auth adapter는 별도 HOLD다.
따라서 production UI mutation은 Auth adapter가 승인·구현되기 전까지 fail-closed 상태를 유지한다.

## 환경

서비스계정은 아래 중 하나만:

- `ERP5_FIREBASE_SERVICE_ACCOUNT_JSON`
- `ERP5_SERVICE_ACCOUNT_PATH` (개발)

service account의 `project_id`가 정확히 `freepasserp5`가 아니면 즉시 실패한다.

## 하지 않은 것

- 실제 credential 입력
- production deployment
- Auth 연결
- 기존 ERP5 settlement_rows 덮어쓰기
- 기존 ERP4 Firebase fallback
- 전자계약
