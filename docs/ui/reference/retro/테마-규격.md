# 테마 규격 — 테마를 하나 더 붙일 때

> 대표(2026-09-06): 「이제 이 ERP 내가 **외부 영업 테마**를 바꿀 건데, 이 테마를 바꿀 때 **문제없게끔**
> 그 테마 규제 어디를 바꿔야 되는지랑, 테마에 따른 배열이나 UX 이런 거를 좀 바꿀 건지 UI 랑 맞춰서 그것도 고민을 해봐.
> **코덱스랑 같이 고민해**」

코덱스 판정 `H-20260905-014`(보완) · 제미나이 `H-20260905-015` 를 받아 **내가 다시 열어서 확인한** 것만 적는다.
커서는 못 돌았다(사용량 한도, 9/24 까지).

## ★★0. 「방식」과 「테마」는 다른 것이다 (2026-09-06 대표)

> 대표: 「일단은 **테마만 바뀌는 게** 있어. 그냥 레트로 그런 테마만 바뀌는 거.
> 그리고 아예 이 테마를 바꿔버리면 **구조 자체가** 바뀌는 게 있어.
> 그래서 **테마와 그 방식을 두 개를 만들어야** 될 거 같아.
> ★테마는 그냥 **껍데기**가 바뀌는 거. 그리고 아예 **구조 자체** — 앱의 관리 ERP 구조 자체가 바뀌는 게 있고」

|  | 방식 (구조) | 테마 (껍데기) |
|---|---|---|
| 무엇이 바뀌나 | **자리와 차례** — 왼쪽에 뭐가 있고 목록이 어디 있나 | **결** — 색·선·입체감·모서리 |
| 누르면 | **화면이 다시 뜬다** (주소가 바뀐다) | **보던 자리 그대로** 옷만 갈아입는다 |
| 코드에서 | `길` (주소) | `값` (뿌리 클래스 `cl-요즘`) |
| 지금 있는 것 | 고전 ERP 방식 · 하루할일 방식 | 고전(레트로) · 현대식 |
| 정본 | `lib/erp/테마.ts` 의 `방식들` | 같은 파일의 `테마들` |

★**전에는 한 목록에 섞여 있었다** — 「고전모드 · 요즘모드」 옆에 「하루할일(본체)」이 나란히 있었다.
껍데기 갈아 끼우기와 구조를 통째로 바꾸는 것을 한 줄에 두면 **같은 급의 선택으로 읽힌다.**
그러다 눌러 보고 구조가 통째로 바뀐다.

★**가르는 잣대** — 처음에 「주소가 바뀌나」로 적었는데 **그건 틀렸다**(코덱스 `H-20260906-001`).
테마도 `?테마=현대식` 으로 주소를 바꾼다. 주소는 결과지 잣대가 아니다.

> ★**잣대는 「마크업이 같나」다.**
> **같은 JSX 가 그리면 테마**(CSS 한 장이면 끝난다) · **화면을 새로 짜야 하면 방식**이다.

이 잣대는 **재진다** — 두 쪽에서 왼쪽 메뉴 수 · 표 줄 수 · 탭 수 · 상세 유무가 같으면 테마다.
고전 ↔ 요즘은 둘 다 `8 · 9 · 1 · true` 로 같다. 하루할일 방식은 애초에 그 셈이 성립하지 않는다.

아래 ①~④ 는 **테마**(껍데기)에 대한 규격이다. 방식을 새로 만들 때는 화면을 새로 짜는 것이므로
`lib/erp/화면들.ts`(무엇을 보여주나)와 `lib/erp/목록.ts`(자료 통로)를 **그대로 쓰는지**부터 본다.

★**아직 하루할일 방식에는 테마가 없다**(`테마쓰나: false`). 자기 결 하나뿐이다.
거기에 고전 결을 씌우려면 화면을 다시 짜야 하고, 그건 껍데기가 아니라 구조다 —
그날이 오면 **방식을 하나 더** 만드는 것이 맞다.

## ★★0-2. 구조는 «둘», 테마는 «여럿» (2026-09-06 대표)

> 「테마는 되게 **여러 가지**가 있을 거고, 구조는 그냥 고전·현대 **이렇게 두 개**가 있겠지.
> 테마는 뭐 다크모드·고전모드·현대모드·간편모드 — 이렇게 **색깔별로**인 거고,
> 사실상 구조는 크게 두 가지. ★뭐 이렇게 **능동형이냐, 할 일을 내려주는 거냐** 그런 식으로」

|  | 구조 (방식) | 테마 (껍데기) |
|---|---|---|
| 몇 개 | **둘** — 늘리지 않는다 | **여럿** — 늘어난다 |
| 무엇이 갈리나 | **일을 어떻게 만나나** | 색 · 선 · 입체감 |
| 고전 | ★**능동형** — 내가 찾아 들어간다 | 레트로 |
| 현대 | ★**할 일을 내려준다** — 일이 나에게 온다 (JPK워크) | 요즘 |
| 앞으로 | — | 다크 · 간편 … |

★**구조는 닫아 둔다.** 셋째를 만들려면 「일을 어떻게 만나나」가 또 갈려야 한다.
화면을 새로 짜는 일이라 함부로 늘리지 않는다.

★**테마는 열어 둔다.** 하나 늘리는 것이 **「표에 한 줄 + CSS 한 장」**이면 된다:

1. `lib/erp/테마.ts` 의 `테마들` 에 한 줄 — 코드 · 이름 · 값 · **클래스** · 무엇
2. 그 클래스를 뿌리로 삼는 CSS 한 장 (본보기 `app/erp-classic/요즘결.css`)
3. `app/erp-classic/결들.css` 에 `@import` 한 줄

화면 코드(`page.tsx`)는 **손대지 않는다** — 뿌리 클래스도 그 표에서 나오고, CSS 도 `결들.css` 가 모아 들인다.
★2026-09-06 에 **임시 테마 하나를 실제로 넣어 재 봤다** — 설정에 뜨고 화면에 걸렸다. 그 뒤 지웠다.

★갚는 만큼 다크가 가까워진다. **다크를 먼저 만들면 안 된다** — 반쯤 밝은 화면이 나오고,
그걸 손으로 덧칠하면 빚이 오히려 는다.

## ① 무엇을 바꿔도 되고, 무엇은 못 바꾸나

★이 표는 **0장을 반영해 다시 짰다**. 전에는 「배치 · 차례」를 **테마가 바꿔도 되는 것**으로 적어 놓고,
0장에서는 그걸 **방식**이라고 적어 두 자리가 어긋나 있었다(코덱스가 짚었다).
**배치와 차례는 방식의 몫이다.** 테마는 결만 만진다.

| | 테마가 바꾼다 | 방식이 바꾼다 | 아무도 못 바꾼다 |
|---|---|---|---|
| **결** | 색 · 선 · 간격 · 모서리 · 입체감 | — | **글꼴** — 프리텐다드 고정 (`docs/글꼴-정본.md`) |
| **배치** | — | 표 ↔ 카드 · 한 화면 ↔ 여러 탭 · 폭 | **뿌리탭 넷** — 할 일 · 조회 · 등록 · 설정 |
| **차례** | — | 화면이 놓이는 순서 · 바로가기 | **업무 처리 순서** — 무엇 다음에 무엇을 하나 |
| **말** | — | 화면에 보이는 이름 | **화면 코드** — `TD-0110` 같은 것 |
| **자료** | — | — | **통로 하나** `lib/erp/목록.ts` · **범위** · **식별키** |
| **뜻** | — | — | **상태색의 뜻** · **「모름 / 빈 값 / 오류」의 구분** |
| **판정·권한** | — | — | 전부 |

★**「모름 / 빈 값 / 오류」를 테마가 다시 정하면 안 된다.** 이게 갈리면 같은 자료가 화면마다 다른 말을 한다.
코덱스가 짚은 것이고, 실제로 그렇게 돼 있었다 — 아래 ②-(라).

★**글꼴은 바꿀 수 없다.** 이건 내 초안이 틀렸고 코덱스가 맞았다.
대표가 「클래식 또는 레트로로 가더라도 글꼴은 프리텐다드」로 못 박았다.

## ② 테마를 하나 더 붙일 때 「조용히 깨질」 자리

에러가 안 나고 **화면만 이상해지는** 종류다. 넷은 이미 겪었고, 둘은 코덱스가 짚어 확인했다.

| | 무슨 일 | 지금 |
|---|---|---|
| (가) | 테마 폴더가 **제 자료.ts** 를 갖고 있어 **176건이 16건**이 됐다 | 고침 — 통로는 `lib/erp/목록.ts` 하나 |
| (나) | `규격.css` 를 안 들여와 **색이 통째로 빈 값**이었다(`/check`·`error`·`not-found`) | 고침 + 검사기가 지킨다 |
| (다) | `화면찾기()` 가 못 찾으면 **첫 화면**을 돌려줘 라벨 셋이 같아졌다 | 라벨만 고침 — ★**함수는 그대로다** |
| (라) | 저장소 실패를 `[]` 로 삼켜 **고장이 「자료 없음」→「시연값」으로 둔갑** | ★**2026-09-06 고침** |
| (마) | 「테마」 링크가 **`/demo`**(가짜 자료 화면)로 갔다 | ★**2026-09-06 고침** — `lib/erp/테마.ts` |
| (바) | `목록보기()` 가 **고객명·연락처·미수를 통째로** 준다 | ★**안 고쳤다** — ③ 참고 |

**(라)** 는 대표의 오래된 잣대를 코드가 어기고 있던 것이다 —
「자료에 구멍이 있으면 **없다**가 아니라 **모른다**」. `통()` 이 `catch { return [] }` 였다.
새 테마도 같은 문으로 들어오니, 여기가 거짓말하면 **테마마다 같은 거짓말**을 한다.

**(다)** 는 아직 남아 있다. `화면찾기()` 는 지금 창을 그릴 때는 되돌림이 맞지만,
새 테마가 자기 화면 목록을 가지면 **없는 코드를 첫 화면으로 바꿔치기**한다.
→ 새 테마를 붙일 때 **「없으면 없다」고 하는 함수**를 따로 둔다.

## ③ ★외부 영업 테마 — 권한이 먼저다

**테마는 보안 경계가 아니다.**

```
지금:  목록보기(갈래) → 직원 로그인만 확인 → 임차인·연락처·미수를 «통째로» 준다
       (lib/erp/actions.ts · lib/erp/목록.ts — 열어서 확인했다)
```

★**열을 숨기는 것으로는 안 막힌다.** 브라우저가 이미 받은 값이다.
코덱스·제미나이가 같은 말을 했고, 코드를 열어 보니 그대로다.

### 그래서 순서가 이렇다

1. **바깥 계정 정책** — 지금 문지기는 **직원 명부**만 통과시킨다(`lib/erp/문지기.ts`).
   외부 영업자는 명부에 없다. **계정이 먼저지 테마가 먼저가 아니다.**
2. **서버가 줄·칸을 걸러서 준다** — `목록보기()` 옆에 「외부용 문」을 따로 낸다.
   같은 통을 읽되 **보낼 것만 보낸다.** 검색·상세·내려받기에도 같은 잣대를 건다.
3. **읽기 전용을 서버가 강제한다** — 테마 속성이 아니라 계정 권한으로.
4. 그 다음에 **테마를 그린다.**

### 보여줄 것 / 가릴 것

| 보여준다 | 가린다 |
|---|---|
| 공개 승인된 차 · 상품 | 다른 고객의 개인정보 (이름 · 연락처) |
| 팔 수 있는 상태 | **미수 · 추심 · 채권** |
| 승인된 제시 가격 · 조건 | **매입원가 · 마진 · 금융** |
| 본인이 맡은 건의 진행 | 남의 건 |

### 배열·UX

- **상품 찾기 → 조건 확인 → 내 진행 건** 순. 직원용은 「오늘 할 일」이 먼저지만, 밖은 **찾기가 먼저**다.
- 폰 카드 중심. 직원용 표는 「전문가 도구」고 밖은 **하나의 목표**에 집중한다.
- **모르는 것은 「모름」, 실패는 「다시」** — 빈 화면으로 얼버무리지 않는다.

## ④ 어디를 고치면 테마가 하나 더 붙나

| 자리 | 무엇 |
|---|---|
| `lib/erp/테마.ts` | **목록에 한 줄** — 코드·이름·길·무엇·로그인 |
| `app/<새테마>/` | 그 테마의 화면. **자료는 `lib/erp/목록.ts` 에서만** 가져온다 |
| `app/규격.css` 들이기 | ★안 들이면 색이 **빈 값**이 된다. 검사기가 잡는다 |
| `app/layout.tsx` | 손댈 것 없다 — 글꼴은 이미 앱 전체에 걸려 있다 |

★**테마 폴더 안에 `자료.ts` 를 만들지 않는다.** 시연값이 필요하면 화면이 비었을 때만 쓰고,
「시연값입니다」를 **반드시 화면에 띄운다.**

# ★외부용 문 — 만들었다 (2026-09-06)

> 대표: 「니 추천 들어 한번 가봐」 — 내 추천은 **권한부터**였다. 그래서 문을 먼저 냈다.

| 무엇 | 어디 |
|---|---|
| 외부 사람 명부 · 허용 칸 · 보일 상태 | `lib/erp/외부영업.ts` |
| 외부 문(로그인) | `lib/erp/문지기.ts` 의 `외부누구냐()` |
| 밖이 부르는 **단 하나**의 서버 문 | `lib/erp/actions.ts` 의 `매물보기()` |
| 새는지 지키는 도구 | `node scripts/외부문-검사.mjs` |

## 어떻게 막나 — 「허용 목록」이지 「금지 목록」이 아니다

```
외부칸 = 번호 · 차종 · 연식 · 법인 · 나갈수있나      ← 이것만 보낸다
```

★**「연락처는 빼라」고 적으면 안 된다.** 나중에 칸이 하나 늘 때 그건 **그냥 나간다.**
**「이 칸만 보내라」**고 적으면 새 칸은 **저절로 막힌다.** 실수의 방향이 반대다.

안 보내는 것: **임차인 · 연락처 · 미수 · 경과 · 단계 · 차대 · 전표 · 월할부 · 취득가 · 시작 · 종료**
★**「상태」도 안 보낸다.** 「대여중이 몇 대인지」도 밖이 알 일이 아니다.
대신 **「지금 / 곧」**만 보낸다. 영업엔 그거면 된다.

상태 말은 「운영현황」 탭의 실측값이다(`lib/erp/ids.ts`).

★**「상품화예정」은 보인다** — 대표(2026-09-06) 「니 추천대로 해」로 내가 정했다.
안 보이면 영업이 **있는 차를 없다고** 말하게 된다. 그게 더 큰 손해다.
★대신 「곧」이라고 **따로 표시한다.** 「지금 된다」고는 결코 말하지 않는다.

★대수 정본(2026-08-25) 기준 쉬는차 SW 1 · PR 1, 상품화예정 SW 9 · PR 0
— 즉 **지금 밖에 보일 차는 열한 대 안팎**이다.

## 명부는 비어 있다

```ts
export const 외부명부: 외부사람[] = [];
```

★**없는 것을 지어내지 않았다.** 외부 영업자가 누구인지 대표가 정하기 전이다.
비어 있으면 **아무도 못 들어온다** — 그게 맞는 기본값이다.

★직원 명부와 **섞지 않았다.** 2026-09-06 에 명부가 두 벌이라 양용득의 메일이 갈려 있던 것을 봤다.
그 실수를 다시 하지 않는다. 직원이 외부 문으로 와도 막히고, 그 반대도 막힌다.

## 도구가 지킨다

```bash
node scripts/외부문-검사.mjs
```

① 허용 목록에 가릴 칸이 끼었나 ② 줄을 통째로 퍼담나(`...줄`)
③ 외부 문이 **외부 명부**로 가리나 ④ 바깥 화면이 **직원용 문**을 부르나

★일부러 허용 목록에 「연락처」를 넣어 **빨간불이 뜨는 것을 확인했다.**
